# Правила ведения учебного репозитория

Эти инструкции относятся к созданию и обновлению материалов курса «Управление данными предприятия» и его HTML-страниц в этом репозитории.

## 1. Организация курса и индекса

- Главная страница сайта — [`index.html`](index.html). Это тематическая программа и навигация по материалам, а не список встреч.
- Показывай темы отдельными разделами страницы, а ссылки на лекции, практикумы, методические пособия и записки размещай внутри соответствующей темы. Не собирай материалы разных тем в параллельные таблицы.
- Текущий порядок разделов индекса:
  1. **Роль Аналитика ERP/MES/CRM системы**
  2. **Производство в ERP**
  3. **Управление активами (ТОиР)**
  4. **Логистика**
  5. **Управление финансами**
  6. **Управление данными**
  7. **Управление проектами и модули системы**
- Логистика находится после управления активами, поскольку занятия по ней ещё не было. Этот порядок показывает последовательность курса в индексе; не выдавай его за официальную нумерацию РПД, если она отличается.
- Для темы 1 указывай методическое пособие **«Концепция прикладного решения ERP»**. Для тем производства и управления активами — **«Управление производством и ремонтами в ERP»**. Методические пособия доступны студентам в личном кабинете. Не представляй их как файлы репозитория, если локального файла нет.
- В теме 2 располагай лекцию и практикумы № 1–8. Если авторские разборы есть только для части практикумов, указывай ссылки на существующие разборы, а для остальных — источник методического задания и отсутствие отдельного авторского разбора.
- В теме 3 размещай материалы по ТОиР, включая пояснительную записку и соответствующее методическое пособие.
- Для темы, по которой ещё нет занятий или авторских материалов, оставляй короткое пояснение вместо пустого списка или выдуманного содержания.
- Официальную ссылку с названием **«Рабочая программа дисциплины»** веди на <https://fa-un.github.io/edm/>. Файл [`edm.md`](edm.md) можно давать отдельно только как «текстовую копию РПД».
- [`INDEX.md`](INDEX.md) поддерживай согласованным с тематической структурой `index.html`.

## 2. Даты и сведения о занятиях

- Рядом с материалом указывай только дату создания первой версии самого материала в формате `ДД.ММ.ГГГГ`, без пояснительного текста.
- Для производных форматов (например, HTML-версии md-файла) не добавляй отдельную дату.
- Для загруженных материалов сначала используй дату создания, встроенную в файл; дату из имени файла используй, если она однозначна. Не подменяй исходную дату датой скачивания, последнего изменения, коммита или публикации.
- Не выводи дату проведения занятия из даты файла. Даты встреч включай только при наличии прямого подтверждения; если точная дата неизвестна, её можно не указывать.
- Не придумывай факт проведения, посещения или завершения практикума. Отделяй подтверждённое от запланированного.
- Для пособий и иных внешних файлов без подтверждённой даты не добавляй предполагаемую дату.

## 3. Материалы и версии

- Авторские учебные материалы оформляй в md и HTML, когда для материала поддерживаются обе версии. Сохраняй одинаковые название, смысл и порядок разделов.
- Имена парных файлов должны совпадать, меняется только расширение. Сохраняй принятый стиль имён репозитория и номера практикумов.
- В HTML-странице добавляй ссылку на главную программу курса и, если есть, на исходный md. В индексе указывай обе версии.
- HTML должен оставаться самостоятельным статическим документом, пригодным для просмотра на компьютере, телефоне и печати. Используй локальные ресурсы и стили; не делай доступ к основному содержанию зависимым от внешнего сервиса.
- Если в Pages публикуются исходные файлы PDF, PPTX или другие вложения, добавляй сами файлы в репозиторий, прямую ссылку на скачивание — в соответствующую тему индекса, а расширение файла — в список копируемых форматов workflow `pages.yml`.
- Включай в страницы только материалы, реально присутствующие в репозитории или доступные по явно приведённой ссылке. Для материалов из личного кабинета указывай, где их найти, но не создавай несуществующие ссылки.
- Сохраняй ссылку на источник и привязывай утверждения к доступному учебному материалу (РПД, методическому пособию, презентации или заданию). Если источник недоступен, не приписывай ему не проверенные значения.

## 4. Определения и схемы создаваемых объектов

Перед схемой дай краткие определения терминов, нужных для её чтения. Определение описывает роль понятия, пример связывает его с заданием.

При необходимости поясняй обозначения схемы: реквизит-ссылка (`att` на рукописном эскизе) хранит выбор другого объекта; табличная часть (`list`) содержит строки со ссылками, количествами и другими данными. Подписывай отношения явно: отступ сам по себе не означает физического подчинения, а обозначает только связь, указанную в подписи (например, состав, принадлежность или переход по ссылке). Стрелка «на основании» обозначает создание документа.

В схеме подписывай тип связи: «реквизит-ссылка →», «строка табличной части →», «принадлежит», «входит в физический состав», «создаётся на основании». Вложенность отступом сама по себе не означает физического подчинения.

Каждый создаваемый именованный объект обозначай жирным заголовком с типом и главным атрибутом, например:

> **Объект эксплуатации: Наименование: Технологическая установка xx.yy**

Для других именованных объектов используй тот же шаблон: `Тип объекта: Наименование: значение`. Для документа вместо «Наименование» показывай его главный идентификатор или ссылку на ключевой объект, например `Заказ на ремонт: Объект эксплуатации: Технологическая установка xx.yy`; номер используй, если он задан или доступен.

Под заголовком перечисляй задаваемые в упражнении реквизиты построчно в формате `Ключ: значение`. Состав табличной части показывай отдельно, перечисляя значения каждой существенной строки в том же формате. Не заменяй заполненные поля общим текстом вроде «настроить параметры».

Используй значения из задания, учебного варианта или слайда. Если конкретное значение зависит от студента или не задано источником, прямо пиши «по варианту студента», «заполняется по шаблону» или «значение в источнике не указано». Не придумывай значения и не превращай условный текст в якобы точное имя поля.

Различай и явно обозначай:

- отдельную запись справочника;
- реквизиты этой записи и ссылки на другие записи;
- табличную часть и её строки;
- строку/этап/операцию внутри норматива;
- документ, созданный для конкретного события, и его связь «создать на основании»;
- нормативное описание и факт выполнения.

После каждой схемы указывай проверяемый результат: какие записи созданы, какие ссылки и табличные строки заполнены и какой статус требуется заданием.

## 5. Публикация сайта

- Сайт — статические HTML-страницы из этого репозитория. Публикацию выполняет workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) после обновления ветки `main`.
- После изменений индекса или HTML проверь ссылки на локальные материалы. Перед утверждением, что обновление опубликовано, проверь завершение workflow и открытие соответствующей страницы GitHub Pages.
